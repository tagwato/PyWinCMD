----------------- ENV VARIABLES EXPANSION -------------

First command line:     
  set "BLA=AAAAAAAAAA aaaaaaaaaaa" & set BLU=UuuuuuuuuU & set BL
Result:
  Success -->  Variables are set

Second command line: 
  dir *.txt &  (echo %BLA% & echo %NOTHING% & echo %BLU%) >"lixo atenção.txt" && type  "lixo atenção.txt"
Result: 
  Success -->  Variables BLA and BLU expanded values are printed inside the file "lixo atenção.txt".
               Because variable NOTHING is not defined, it correctly appears as a text: '%NOTHING%'
               (The echo of %NOTHING% should NOT appear as '' nor as a message 'ECHO is on/off')

Third command line:     
   cmd /c "exit 0" &  echo %errorlevel% & cmd /c "exit 888"  & echo %errorlevel% & if errorlevel 888 (echo Captured)
Result:
   Success -->  Echoes: 0, 0, Captured     (if you try this command on the NATIVE cmd prompt, would get the same results)

Fourth command line: 
   echo %errorlevel% & cmd /c "exit 888"  & echo %errorlevel% & if errorlevel 888 (echo Captured)
Result:
   Success -->  Echoes: 888, 888, Captured (if you try this command on the NATIVE cmd prompt, would get the same results - PS- execute twice)
Fifth command line: 
  chcp & cd non_existent_folder
Success -->   If the command line verbosity is ON (via F5), then a final message says that current errorlevel is 1 (because the CD command fails )
              Typing 'echo %errorlevel%' after the command line execution also prints 1.

-----------------  SPECIAL COMPLEX CASES --------------

dir *.txt & (   time / ?   & python -m pip list  & echo MMMMMM ) > "Saída atenção.txt 2>&1&notepad&&(echo 1 & echo 2)>>"Saída atenção.txt" 
  Result: PywinCMD does NOT allow running this line, prints an 'Unbalanced quotes' error and ask for corrections.  
          -- If running in the native CMD prompt, it would raise an error message too --about unexpected text-- and would NOT execute anything.

dir *.txt & ((  time / ?   & python -m pip list  & echo MMMMMM ) > "Saída atenção.txt" 2>&1&notepad&&(echo 1 & echo 2)>>"Saída atenção.txt" 
  Result: PywinCMD prints an 'Unbalanced parentheses' error  (which occurs before 'time') and asks if user wants to proceed.
          -- if the cmdline were running in the native CMD prompt, it would print a "More?" message, asking for completion
             (except when the mismatch is due to parenthesis in folder/file names or in echo commands, those are accepted)
          -- But PywinCMD can not show the "More?" message, because it is running CMD /C which is non-interactive)  
             So, in case the user proceeds, the "More?" is not displayed and the execution is just canceled.
  Q - So, why doesn't PyWinCMD just forbid unbalanced parenthesis? A- Because they MUST be allowed in folder/filenames and echo arguments.

dir *.txt & (  time / ?   & python -m pip list  & echo MMMMMM ) > "Saída atenção.txt" 2>&1&notepad&&(echo 1 & echo 2)>>"Saída atenção.txt" && echo ****** FILE CONTENT ****** && type  "Saída atenção.txt"
  Result: Success
        -- Notepad opened in background, without freezing the prompt line
        -- Content of "Saída atenção.txt" printed with the 'time' command help, after the header "****** FILE CONTENT ******"
